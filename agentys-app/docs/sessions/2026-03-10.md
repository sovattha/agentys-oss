## Session 2 — Multi-compte IMAP + OAuth placeholder detection

### Changements

**Multi-compte : fix "toujours Gmail après switch"**
- `accounts.py` : `_ensure_db_account()` crée une ligne SQLite Account à l'ajout et à l'activation d'un compte (manquait → `account_id` fallback=1 = Gmail)
- `imap_adapter.py` : `resolve_folder_name()` résout les dossiers IMAP via flags serveur (Sent/Trash/Spam/Drafts/Archive) au lieu de hardcoder `[Gmail]/...`
- `smtp_adapter.py` : délègue `resolve_folder_name()` à l'adaptateur IMAP interne
- `routes.py` : 4 folder mappings (list_emails, 2 bg refresh, prefetch) utilisent maintenant `resolve_folder_name()` quand le provider le supporte

**OAuth placeholder detection**
- `config.py` : `is_placeholder()` / `is_env_set()` — détecte `your-client-id`, `changeme`, `TODO`, etc.
- `oauth.py`, `factory.py`, `wizard.py` : utilisent les helpers au lieu de `bool(os.getenv(...))` qui était truthy sur placeholders

**Error propagation "Unknown error"**
- `api.ts` : `data.error || data.message || 'Unknown error'` (lisait seulement `data.error`)
- `accounts.py` : réponses 401/500 du test endpoint incluent maintenant le champ `error`

**Cleanup**
- `auth.py` : suppression import `requests` non utilisé (ruff F401)
- `QuickEventPopover.tsx`, `DeepFocusMode.tsx` : prefix `_` sur params non utilisés (TS6133)

### Découvertes
- Le Account Manager (multi_accounts.py) est un store JSON en mémoire, mais le cache email est en SQLite scopé par `account_id` (entier DB). Sans ligne DB pour un compte, le fallback `account_id=1` sert les emails du premier compte.
- L'IMAP de Hotmail/Outlook utilise `Sent Items`, `Deleted Items`, `Junk` — aucun dossier `[Gmail]/...`.

### Décisions
- Ajout de `resolve_folder_name()` sur l'adaptateur IMAP plutôt que mapping centralisé dans routes.py : le provider connait ses propres dossiers via IMAP LIST flags.
- `_ensure_db_account()` est idempotent (vérifie existence avant insert) — safe pour les comptes déjà en DB.

- 8 blocs `except: pass` remplacés par `logger.debug(..., exc_info=True)` — les erreurs silencieuses compliquent le debug en prod

**Icône "Your Agents" : redesign sparkles**
- Remplacement du neural network 2-3-2 (19 éléments SVG, lignes invisibles à 42px) par 3 sparkles connectées (6 éléments, filled shapes, haute visibilité sur fond teal)

### Décisions
- Sparkles (Option A) plutôt que neural net simplifié (Option B) : le motif "sparkle" est universellement reconnu comme "IA" en 2026, et les filled shapes garantissent la lisibilité à petite taille
- Cleanup DB avant `remove_account()` : le JSON store ne connaît pas les IDs SQLite, donc le cleanup doit se faire tant que l'email est encore accessible

### Découvertes

### Décisions
- Sync markdown → SQLite au moment du save (fire-and-forget) plutôt qu'en temps réel : évite les appels API à chaque keystroke
- Category metadata en commentaire HTML `<!-- category: FAQ -->` : invisible dans le rendu markdown, préserve la compatibilité avec les parseurs existants
