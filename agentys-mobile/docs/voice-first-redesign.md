# Voice-first Drive Mode — turn-taking redesign

Goal: move Drive Mode toward a **minimal, speech-only** flow and fix the
"user speaks / AI speaks / vice-versa" collisions.

## The two root causes

1. **Latency / half-duplex.** STT is file-based & batch (`useVoiceDictation`
   records → uploads → `/api/transcribe`). ~1.5–2 s of dead air after every
   user utterance → users re-speak → collide. The most important reads
   (draft preview / re-read / `asking_send`) deliberately use plain `speak()`
   (not `speakAndListen`) to dodge the iOS PlayAndRecord earpiece-routing bug,
   so those reads are **tap-only** to interrupt.
2. **Too many turns.** The machine forces 5–7 TTS↔mic handoffs per email, and
   each spoken protocol question (*"J'envoie ?"*, *"Tu veux l'écouter ?"*) is a
   full TTS round-trip **and** a collision site.

Fixing only one leaves the rhythm broken. The plan does both.

## What shipped (Steps 1–3)

### Step 1 — Earcons replace spoken protocol  ✅ on by default
The AI now speaks only **content** (email summary, draft). Turn-handoffs use a
3-tone, $0, sub-30 ms earcon vocabulary instead of spoken questions:

| earcon | meaning | fires |
|--------|---------|-------|
| `turn`  | "your turn, I'm listening" | replaces every `tts.shouldSend` / `tts.askDraft` prompt |
| `tick`  | "got it, capturing"        | `onVoiceStart` (the instant the mic hears you — sub-100 ms feedback during the batch-STT gap); archive confirm |
| `done`  | "sent"                     | `approveDraftAndNext` success |
| `alert` | "error / destructive"      | send-fail, delete, archive-fail |

Assets: `assets/earcons/*.wav`, regenerated by `python scripts/gen-earcons.py`.
Hook: `src/hooks/useEarcons.ts` (preloads, `play(name)` is stable & defensive).
Haptics are kept paired for redundancy (driver can't always hear in a car).
The visual `StatusPill` ("Send?", "Draft it?") stays as the silent backstop.

### Step 2 — Full-duplex reads  🔒 flag-gated `FULL_DUPLEX_READS = false`
Behind one flag in `useDriveMode.ts`. When `true`: one `voiceChat` session
(AEC + forced speaker) opens once per session; the **primary** draft reads
(post-generate read + existing-draft read) route through `speakAndListen` so
they're voice-interruptible. (Explicit re-read paths — `wantsDraftRead`,
`REPEAT`, `asking_preview` "yes, listen" — still use plain `speak()`; gate them
too in a follow-up once Step 0 confirms the routing.) Default `false` = today's
exact behavior (zero regression). **Do not flip until Step 0 passes.**

### Step 3 — Single-utterance send + act-then-undo  ✅ on by default
If a dictation ends with an explicit send verb (*"…et envoie"*, *"…and send
it"* — `extractSendDisposition`, strict trailing-only match), the verb is
stripped from the body and, after the draft is read, the machine enters the
new `undo_window` state: a `tick` + Medium haptic + a single **undo** chip,
mic open for `UNDO_WINDOW_MS` (4 s). Any speech (or the chip / `rejectAndRelisten`)
aborts to `reviewing` keeping the draft; silence → auto-approve (`done`).
No spoken *"J'envoie ?"*. The chip is the latency-proof escape hatch (tap needs
no STT). `asking_preview` / `asking_send` remain intact for the non-explicit path.

## Step 0 — device-verify checklist (gates `FULL_DUPLEX_READS`)

Run on a **real iPhone with the dev-client build** (Expo Go has no native
`AgentysAudio` module → everything degrades to the safe fallback):

- [ ] During a draft read with `configureForVoiceChat()` active, is TTS
      **audibly loud** (speaker, not earpiece)? If yes → the "must use plain
      `speak()`" rule is obsolete; flip `FULL_DUPLEX_READS = true`.
- [ ] Can a bundled earcon play through the **speaker** (not earpiece) while a
      record session is active? If no → add a native `playEarcon` path
      (`AudioServicesPlaySystemSound`) in `modules/agentys-audio` that ignores
      the AVAudioSession category.
- [ ] Barge-in: speaking over a draft read cuts the TTS and is transcribed
      cleanly (AEC removes the echo). If clean, `detectTailCommand` can be
      retired (it only exists to recover commands from echo-contaminated audio).

## Step 4 — streaming re-architecture  🔒 CODE SHIPPED, flag-gated `STREAMING_STT = false`

Built 2026-06-10 (branch `feat/voice-first-mobile`) — all the pieces exist and
are unit-tested; the flag stays OFF until the Step-0bis device checklist below
passes on a real iPhone dev-client build.

What shipped:
- **Native mic tap** : `AgentysAudioModule.swift` → `startMicStream(sampleRate)`
  / `stopMicStream()` — AVAudioEngine input tap, AVAudioConverter vers PCM16
  mono 16 kHz, frames ~85 ms émises en base64 via l'event `onMicFrame`.
  Bindings TS : `MIC_STREAM_AVAILABLE` (distinct de `NATIVE_AVAILABLE` — un
  vieux build natif a le module sans la fonction).
- **Backend proxy** : `app/api/stt_stream.py` — events `stt_stream_start/chunk/
  stop` sur le namespace /daemon existant (auth connect réutilisée), relais
  vers Deepgram live (nova-3, `interim_results`, `endpointing=300`,
  `utterance_end_ms=1000`, `vad_events`, keyterms par compte). Retours :
  `stt_partial`, `stt_final{speech_final}`, `stt_utterance_end`,
  `stt_speech_started` (= signal barge-in <300 ms), `stt_stream_closed`.
  Caps : 1 stream/connexion, 2/compte, 50 global, 5 min, 30 s d'inactivité.
  Usage facturé en DictationUsageLogRow (provider `deepgram_stream`).
- **`useStreamingStt`** : UNE session Deepgram pour toute la session Drive
  (zéro coût de connexion par tour), `listen()` = prochaine utterance résolue
  par l'endpointing sémantique, pré-buffer 1,5 s des finals hors-listen (le
  barge-in n'est jamais perdu), relance transparente ×2 sur fermeture serveur,
  fallback batch automatique (`onSessionLost`).
- **Intégration `useDriveMode`** : branche streaming dans `startListening`
  (partiels → transcript live), barge-in sémantique dans `startSession`
  (SpeechStarted → stop TTS + earcon tick), fermeture dans reset/farewell.

Reste à faire une fois le flag ON (validé sur device) :
- supprimer `detectTailCommand` (l'AEC + barge-in sémantique le rendent inutile)
- fusionner `speak()`/`speakAndListen()` en un `say()` unique
- passer les paths de relecture explicites (`wantsDraftRead`, REPEAT) en
  full-duplex
- optionnel : turn-detector sémantique (LiveKit open model) sur le transcript.

## Step 0bis — device-verify checklist (gates `STREAMING_STT`)

Sur un iPhone réel avec un dev-client build FRAIS (le module natif a changé) :

- [ ] Step 0 originel passe (TTS forte pendant configureForVoiceChat, earcons
      audibles, barge-in AEC propre) → flip `FULL_DUPLEX_READS`.
- [ ] `AgentysAudio.startMicStream(16000)` retourne true et `onMicFrame` émet
      des frames régulières (~12/s) pendant qu'on parle.
- [ ] Les frames passent le socket : `stt_partial` arrive <500 ms après le
      début de parole (vérifier les logs backend `[stt-stream] open`).
- [ ] Pendant une lecture TTS, parler coupe la TTS (`stt_speech_started`) et
      le transcript est PROPRE (pas d'écho TTS — l'AEC fait son travail).
- [ ] Une session de 6 min déclenche la relance transparente (cap 5 min) sans
      que l'utilisateur le remarque.
- [ ] Backgrounder l'app (UIBackgroundModes audio) : la session survit écran
      verrouillé.
      → Alors flip `STREAMING_STT = true` dans useDriveMode.ts.

## Ce qui a AUSSI shippé le 2026-06-10 (indépendant du flag)

Actif immédiatement, sans build natif :
- **Voice agent** (`/api/voice/agent`) : intents composés (« archive ça et
  lis-moi le suivant »), dictée inline avec envoi (« réponds que ok et
  envoie »), questions sur l'email courant (« il proposait quelle heure ? » →
  réponse parlée SAY). Remplace `/voice/intent` comme fallback LLM.
- **TTS chunkée** (`lib/ttsChunks` + useTts) : premier son en ~400-700 ms sur
  les textes longs (avant : 1,5-3 s), synthèse du chunk N+1 pendant la lecture
  du chunk N, prefetch aligné sur le même découpage.
- **Act-then-undo généralisé** (`lib/pendingActions`) : archive/delete/envoi
  jouent l'earcon et avancent immédiatement, l'API part après 5 s (8 s envoi),
  « annule » récupère l'action, journal SecureStore rejoué au boot (crash-safe).
- **Brief parlé d'entrée** (`/api/voice/briefing`) + **entrée zéro-toucher** :
  Siri Shortcut → `agentys://?autostart=mixed` → l'app parle en premier et
  démarre la session sans un seul regard. (Créer le Shortcut : Ouvrir l'URL →
  `agentys://?autostart=mixed`, phrase « fais mes emails ».)
- **Télémétrie voice-to-voice** (`lib/voiceMetrics` → `/api/voice/metrics`) :
  turn_latency_ms (budget <1 s), stt/tts latency, barge-ins, undo, misses.
- **Speakable localisé** : le registre parlé suit la langue du device (fr/en/es),
  plus le français hardcodé.
